Add a new Heathrow Flights feature into the existing app without removing, replacing, or breaking any existing functionality. This must be an additive change only. Do not remove any current displayed information, routes, components, styling, data sources, zones, cards, or navigation items.

Goal:
Create new Heathrow Arrivals and Heathrow Departures zones in the app, powered by backend API routes that fetch and normalise Heathrow flight data server-side.

Important architecture requirement:
Do not scrape the public Heathrow website pages.
Use Heathrow Developer Portal / Flights API integration patterns.
Build this as a backend-normalised data source with frontend zones consuming our own API routes.

Context:
Heathrow provides developer APIs for flight information including arrivals, departures, real-time flight details, status, gates and terminals. Build the app integration around that model, using environment variables for credentials and a service wrapper so the upstream can be changed without affecting the frontend.

Requirements

1. Preserve existing functionality
- Do not remove anything currently working
- Do not delete existing UI or routes
- Do not remove any displayed information
- Do not replace unrelated components
- Only add the new Heathrow functionality in a compatible way

2. Backend Heathrow data module
Create a new backend module for Heathrow flight data.

Suggested file names:
- lib/heathrowFlights.js
- lib/heathrowConfig.js
- routes/heathrow.js

The module must:
- Support arrivals and departures
- Be written in Node
- Use the project’s existing module system (ESM or CommonJS)
- Use fetch with timeout and AbortController
- Read API base URL and credentials from environment variables
- Never hardcode secrets
- Support short in-memory caching with configurable TTL
- Support stale-cache fallback if the upstream fails
- Normalise the data into a stable frontend-friendly shape
- Export functions such as:
  - getHeathrowArrivals()
  - getHeathrowDepartures()
  - searchHeathrowFlights() if useful
  - clearHeathrowFlightsCache()
  - createHeathrowArrivalsHandler()

4. Backend API routes
Add the following routes:

- /api/data/heathrow/arrivals
- /api/data/heathrow/departures

Optional support routes if helpful:
- /api/data/heathrow/flights/search
- /api/data/heathrow/flights/:flightNumber

Routes must:
- Return JSON only
- Set Cache-Control headers
- Support optional query params where sensible, such as:
  - terminal
  - airline
  - flight
  - limit
  - date
- Validate inputs sensibly
- Return 502 JSON error if the upstream fails and there is no stale cache
- Return stale cached data with a stale flag if refresh fails but cached data exists
